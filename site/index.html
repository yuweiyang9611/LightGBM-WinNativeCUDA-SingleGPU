01 / 项目概览

目标不是“编译通过”，而是形成完整交付闭环。

单卡训练不需要 GPU 间集合通信。本项目把计算路径与多卡通信依赖拆开， 再逐层解决 Windows 工具链、二进制封装和目标机验证问题。

核心结果 01

原生 CUDA DLL

以 Visual Studio、MSVC 和 NVCC 生成 lib_lightgbm.dll，一次训练使用一张 NVIDIA GPU。

Python 体验 API

调用方式保持一致

仍通过 lgb.train 或 sklearn API 使用，只需设置 device_type="cuda"。

交付形式 03

从 wheel 到便携包

覆盖联网安装、断网 wheelhouse，以及无需预装 Python 和 VC++ Runtime 的便携测试。

验证范围 PTX

原生与 JIT 双路径

同时检查 cubin、relocatable PTX，并分别执行原生代码和强制 PTX JIT 训练。

02 / 做了什么修改

七个关键改造，打通整条 Windows CUDA 路径。

每一项都对应一个明确的构建、运行或交付问题，并通过源码或自动化测试固定下来。

01

依赖边界

把 NCCL 从 CUDA 必选项拆成多卡可选项

单 GPU 只做本卡计算，不应被多卡通信库阻塞。

怎么改
新增 USE_NCCL；按条件执行库查找、头文件包含、源码加入、宏定义与链接。无 NCCL 时保留内部接口占位类型。
边界
device_type="cuda" 且 num_gpu > 1 时主动报错，避免误入不可用路径。
CMakeLists.txt ↗
02

编译工具链

适配 MSVC、NVCC 与 bundled fmt

让 CUDA 13.2 的设备前端和 Windows 主机编译器使用各自正确的参数与类型。

怎么改
MSVC 路径使用 /utf-8、/bigobj 与 NOMINMAX，不再传入 Unix 专用的 -fPIC、-Wall。
fmt 修复
在构建目录复制头文件并应用 UTF-32 workaround；不直接修改第三方源码，且在输入版本不匹配时立即停止配置。
兼容补丁 ↗
03

二进制链接

让 Visual Studio 真正执行 CUDA device-link

CUDA 对象来自 object library 时，最终 DLL 仍必须完成设备符号解析并带上 fatbin。

怎么改
开启 separable compilation 与 device-symbol resolution；为最终目标加入空的 cuda_link.cu，显式触发 Visual Studio CUDA 链接步骤。
运行库
选择 Shared CUDA Runtime，与 MSVC /MD 对齐，避免静态 cudart 引入的 CRT 冲突。
设备链接锚点 ↗
04

源码兼容

清理 Windows 64 位类型与宏冲突

修正只在 MSVC / NVCC 组合下暴露的编译差异。

怎么改
CUDA 可见的数值常量改为 constexpr；使用 size_t{1} 保证模板参数同型。
宏隔离
将 kernel 模板参数重命名为 USE_NCCL_REDUCTION，避免与构建宏发生预处理替换。
源码契约测试 ↗
05

Python 打包

把预编译 DLL 封装成正确的 Windows wheel

包含原生 DLL 的包不能继续被标记为跨平台纯 Python 包。

怎么改
按 sysconfig.get_platform() 重标 wheel，将 Root-Is-Purelib 设为 false 后重新打包。
可识别性
支持 PEP 427 build tag，例如 1cuda132sm89ptx，在不改 Python 包版本的前提下标识 CUDA 变体。

06

离线交付

提供 wheelhouse 与零安装便携测试包

覆盖断网安装，以及不允许改动目标机环境的快速 CUDA 验证。

离线包
先验证 SHA-256，再通过 pip --no-index --find-links 安装 LightGBM 和依赖。
便携包
组合 CPython embeddable、MSVC/OpenMP app-local DLL、隔离启动器和冒烟测试；不修改系统 PATH、注册表或用户 Python。

07

质量闭环

建立从源码契约到真实训练的验证体系

不只验证“构建成功”，还验证产物内容、运行路径、训练结果和能力边界。

怎么测

双路径

运行时调用链

没有另写一套 Python CUDA 接口。

Python 包装层继续通过 ctypes 调用 C API，随后进入 C++ GBDT 与 CUDA Tree Learner。修改集中在构建、链接和 CUDA 能力边界，应用侧只选择 CUDA 设备。

  1. Python API
  2. ctypes / C API
  3. lib_lightgbm.dll
  4. CUDA Tree Learner
  5. NVIDIA GPU
train_cuda.py 
params = {
    "objective": "regression",
    "device_type": "cuda",
    "gpu_device_id": 0,
    "num_gpu": 1,
}

model = lgb.train(
    params,
    train_set,
    num_boost_round=100,
)

06 / 兼容边界

明确支持范围，也明确不做过度承诺。

PTX 提供的是向前 JIT 能力，不会把 8.9 代码变成对旧架构的反向兼容。

目标执行路径当前状态要求 / 说明
Compute Capability 8.9RTX 40 / RTX Ada / L4 等sm_89 cubin已实测文档基线为 R580+；当前实测驱动 610.88
Compute Capability > 8.9更新 NVIDIA 架构compute_89 PTX JIT候选建议 R595+，需要目标 GPU 实机验证
Compute Capability < 8.9例如 sm_86 / sm_80无可用代码不兼容需要额外编译对应 cubin 或更低版本 PTX
多 GPU 训练num_gpu > 1NCCL 集合通信未包含当前 Windows 产物使用 USE_NCCL=OFF
i

目标机无需安装 CUDA Toolkit。运行时仍需要 Windows x64、兼容的 NVIDIA GPU 与驱动；普通 wheel / wheelhouse 还需要对应 Python 和 VC++ Runtime，便携包已将后两者放入包内。
